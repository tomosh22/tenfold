# tenfold "vs-dark": Visual Studio 2022 default Dark theme (OPEN_QUESTIONS #7: "as close to Visual Studio as possible").
# The application default (ui.theme = vs-dark). Same file format as settings.default.txt; only color.* and token.* keys.
#
# Sources (details in docs/VS_BEHAVIOUR.md section 5):
#   [S34] Microsoft Learn, "Color value reference for Visual Studio" (Dark column, VS 2017-2022): shell, tabs, menus,
#         scrollbars, input fields, selection, status bar.
#   [S35] Microsoft's "Visual Studio 2019 Dark (C++)" theme in vscode-cpptools (ported from VS): editor and token colours.
# Values with no source are marked "[?]" inline; correct them by copying this file to <user config dir>/themes/vs-dark.txt
# (or <workspace>/.tenfold/themes/) and editing. Still unsourced (see OPEN_QUESTIONS #19, needs a screenshot):
#   * Chrome: dirtyMarker #DCDCAA, statusHover #1C97EA, status bar while debugging #CA5100 and without a solution #68217A
#     (both from memory), tabAccent line (VS has none).
#   * Editor: current-line outline colour #464646 (shape is documented), editor selection #264F78, find highlight,
#     bracket match, whitespace dots, column guide, caret, build error / warning marks.
#   * Squiggles: error / warning / info (VS: red, green, grey dots; no hex found).
#   * Git margin: added / modified / deleted, inline diff block, fold marker, tab VCS marks.
#   * Terminal: all of it (background #1E1E1E, foreground #CCCCCC, the ANSI palette).
#   * Tokens: string #D69D85 ([S35] has #CE9178), number / enum members, macro #BD63C5 ([S35] has #BEB7FF for
#     function-like macros), template parameter and concept #4EC9B0, debugger current statement #FFEE62.
# Not expressible yet (no widget support, so no key): string escape sequences (VS #FFD68F), user-defined literals, XML
# doc tags. `default` is a plain keyword (the line lexer cannot tell `default:` from `= default`).
